# ESP32-S31

See the [development-board profile](../boards/esp32-s31/README.md). The cited silicon has RV32IMAFC and the port uses one core. Its soft-float ABI and closed radio integration belong to the OS implementation.

[ESP-Mosaico](../boards/esp-mosaico/README.md) has a separate board profile for its
revision-dependent HMI, power and expansion wiring. The development-board port
does not establish runtime support on Mosaico.

## ROM working memory during early boot

ESP-IDF at `d445e947156f276dfe0db5804e4edf6ae90fe6fb` marks
`[0x2f07afb0, 0x2f080000)` as the ROM-reserved startup region in its
[heap memory layout](https://github.com/espressif/esp-idf/blob/d445e947156f276dfe0db5804e4edf6ae90fe6fb/components/heap/port/esp32s31/memory_layout.c).
The lower bound is `SOC_ROM_STACK_START - SOC_ROM_STACK_SIZE`:
`0x2f07cfb0 - 0x2000`, using the pinned
[SoC definitions](https://github.com/espressif/esp-idf/blob/d445e947156f276dfe0db5804e4edf6ae90fe6fb/components/soc/esp32s31/include/soc/soc.h).
The separate [linker definition](https://github.com/espressif/esp-idf/blob/d445e947156f276dfe0db5804e4edf6ae90fe6fb/components/esp_system/ld/esp32s31/ld.hp_mem_defs)
sets `SRAM_SEG_END` to `0x2f07afc0`, 16 bytes above that lower bound.

An SRAM bootstrap that retains ROM working state must account for this region
when placing code, BSS, global data, heaps and every hart's stack. Preserving
exported pointer slots alone does not establish that the state they reference
survives. Reclaiming startup memory needs an explicit lifetime contract.
These are source-level boundaries for this IDF snapshot; they do not establish
the cause of a device hang or the behavior of another ROM revision.
